## Mandatory additional implementation-time tests

The current test-first branch predates the Phase 3 production modules. Several tests intentionally specify expected module contracts and cannot pass until those modules are implemented. During implementation, add these integration checks rather than replacing them with mocks:

1. Run two independent API/worker processes against PostgreSQL and prove the database lease serializes the same workspace/provider/player while allowing unrelated outputs to progress.
2. Expire a lease after worker termination and prove safe takeover; prove a live lease cannot be stolen.
3. Exercise connect, refresh, scope downgrade, authorization expiry, reconnect, disconnect, and disconnect-and-remove-data through each real adapter's auth lifecycle.
4. Capture API responses, browser serialization, structured logs, thrown errors, and audit payloads; assert that access/refresh tokens, client secrets, authorization headers, and credential ciphertext never escape.
5. Verify provider-specific queues cannot become the source of truth for request order, moderation state, or request lifecycle; the PostgreSQL isolation test must prove request state and logical queue order remain unchanged.
6. Exercise each manual recovery action through authenticated API endpoints and verify audit records and unchanged media identity.
7. Test rights report state transitions, evidence retention, escalation permissions, and actual content/provider/workspace enforcement against PostgreSQL.
8. Keep live-provider tests deterministic and safe: use mocked HTTP transports or provider sandbox accounts; do not require real playback, scrape private data, or rely on provider uptime in ordinary CI.

## Release gates and operator documentation

- Each provider needs an operator-facing technical, authorization/scope, availability/failure, contractual/terms, and rights-use assessment. Owner risk acceptance is not a license or permission.
- Public launch remains blocked until a qualified legal reviewer has approved both the policies and the operational procedures. Software tests can verify the recorded approval gate, not the quality or legal sufficiency of legal advice.
- The controls reduce operational risk; they do not guarantee legal compliance.


The active `playback-manual-recovery.test.mjs` suite exercises retry, reroute, skip, dismiss, actor/reason attribution, authorization rejection, and media identity preservation. The parallel copy under `apps/api/test/roadmap/` is a historical test-first artifact and is not part of the active suite.
